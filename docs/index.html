Why a pairing makes this possible

A pairing is a map e : G1 × G2 → GT with one useful property: e(a·P, b·Q) = e(P, Q)a·b. Exponents move across the map, so checking a signature is a single equality — no need for the lab's secret key.

e(σ, Q)  =  e(H(m), pk)

pk = sk·Q and σ = sk·H(m), so both sides come out to e(H(m), Q)sk. If anyone changes the report, H(m) changes and the two sides stop matching.

The lab generates its signing keypair

St. Mary's lab creates one keypair. The secret key sk never leaves the lab's server; the public key pk is published so anyone can check a report.

The lab signs a report, the pharmacy checks it

A patient's fasting-glucose result is signed, then verified against the lab's public key. The signature σ is short — a single point on the curve — but bound to the exact bytes of the report.

Try changing a value after signing — say 92 to 192 mg/dL — and verify again. One changed digit and the report no longer verifies, so a falsified lab result is caught.

Two reports, one signature

Sign both of the patient's reports, then add the signatures together. The sum is one signature the same size as either input, and it still verifies both reports — the insurer checks a whole visit with a single step. ECDSA has no equivalent operation.
